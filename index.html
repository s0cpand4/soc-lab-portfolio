Cyber Security Monitoring & Detection Lab

A fully self-hosted, segmented home lab featuring a Wazuh SIEM integrated with an n8n-based SOAR pipeline that automatically triages alerts and delivers Gmail notifications — built entirely from open-source components at zero software cost.

Wazuh 4.14 n8n (Docker) pfSense CE 2.6 Ubuntu Server 24.04 Windows Server 2019 Kali Linux Gmail API / OAuth2 VMware Workstation Pro

Project Overview

Modern SOC teams don't just detect — they respond. This lab demonstrates an end-to-end detection and automated response pipeline, from network-level attacks launched from Kali Linux through to a formatted email landing in an analyst's inbox within seconds.

🎯 Objective

Build a realistic SOC environment where high-severity alerts trigger automated email notifications without manual analyst intervention.

🧩 Scope

Full lifecycle: network segmentation, SIEM deployment, endpoint agent enrollment, attack simulation, alert correlation, and SOAR automation.

💰 Constraint

100% open-source stack, self-hosted on a single physical host. No cloud subscriptions, no licensing fees, no paid tiers.

Design Principles

① Segmentation First

Attacker, target, and monitoring networks are isolated. This mirrors real enterprise zoning and prevents lateral movement during simulation.

② Realistic Detection

The SIEM correlates events, applies severity thresholds, and only escalates meaningful signals — not raw noise.

③ Automated Response

Detection without action is just noise. Every high-severity alert is triaged and delivered automatically.

Architecture

The environment runs on VMware Workstation Pro with pfSense acting as the central router, firewall, and DHCP server. Each security tool lives on its own isolated network segment, mirroring enterprise network zoning practices.

n8n Setup & OAuth2 Configuration

Deploy n8n in Docker and connect it to the Gmail API via OAuth2 — including the private-IP workaround required for lab environments.

Prerequisites

  • Ubuntu Server 24.04 LTS VM (2 vCPU, 4 GB RAM, 30 GB disk)
  • Static IP assigned (e.g., 192.168.1.135)
  • Internet access for pulling Docker images
  • A Gmail account for sending alerts

Docker Installation

# Update and install prerequisites
sudo apt update && sudo apt upgrade -y
sudo apt install -y ca-certificates curl gnupg

# Add Docker's GPG key
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
  sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

# Add the repository
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# Install Docker Engine
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io \
  docker-buildx-plugin docker-compose-plugin

# Verify
sudo docker run hello-world

# Add user to docker group
sudo usermod -aG docker $USER
newgrp docker

Google Cloud OAuth2 Setup

Why the SSH tunnel? Google blocks OAuth2 redirects to private IP addresses (RFC1918). To work around this, we use an SSH tunnel so the browser sees localhost instead of 192.168.1.135.

Step 1 — Create a Google Cloud Project

  1. Go to console.cloud.google.com
  2. Create a new project (e.g., n8n-SOAR-Lab)
  3. Select the project from the dropdown

Step 2 — Enable the Gmail API

  1. Navigate to APIs & Services → Library
  2. Search for Gmail API
  3. Click Enable

Step 3 — Configure the OAuth Consent Screen

  1. Go to APIs & Services → OAuth consent screen
  2. Choose External → Create
  3. App name: n8n Lab; fill in your email fields
  4. On Scopes, click Save and Continue (nothing needed here)
  5. On Test users, add your Gmail address
    ⚠️ This step is critical. If your email isn't a test user, Google will block the app.

Step 4 — Create OAuth2 Credentials

  1. Go to APIs & Services → Credentials
  2. Click + CREATE CREDENTIALS → OAuth client ID
  3. Application type: Web application
  4. Name: n8n Gmail
  5. Authorized redirect URI: http://localhost:5678/rest/oauth2-credential/callback
  6. Click Create
  7. Copy the Client ID and Client Secret

Step 5 — Start the SSH Tunnel

From your Windows machine (or wherever your browser runs):

ssh -L 5678:localhost:5678 socpanda@192.168.1.135

Keep this terminal window open. Then access n8n at http://localhost:5678.

Integration Script

The Python script is the bridge between Wazuh and n8n. Wazuh's integratord daemon invokes it whenever an alert meets the configured severity threshold.

Create the Script

Save as /var/ossec/integrations/custom-n8n.py:

#!/usr/bin/env python3
"""
Wazuh → n8n integration script.

Invoked by the Wazuh integratord daemon when an alert matches the
configured severity threshold.
"""

import sys, json, os, requests

# --- Configuration ---
WEBHOOK_URL = "http://192.168.1.135:5678/webhook/wazuh-alerts"
LOG_FILE = "/var/ossec/logs/integrations.log"

def write_log(message):
    try:
        with open(LOG_FILE, "a") as f:
            f.write(f"[custom-n8n.py] {message}\n")
    except Exception:
        pass

def main():
    if len(sys.argv) < 2:
        write_log("[ERROR] Missing alert file argument.")
        sys.exit(1)

    alert_file_path = sys.argv[1]

    if not os.path.exists(alert_file_path):
        write_log(f"[ERROR] Alert file not found: {alert_file_path}")
        sys.exit(1)

    try:
        with open(alert_file_path, "r") as f:
            alert_data = json.load(f)
    except Exception as e:
        write_log(f"[ERROR] Failed to read alert JSON: {e}")
        sys.exit(1)

    try:
        response = requests.post(WEBHOOK_URL, json=alert_data, timeout=10)
        response.raise_for_status()
        write_log(f"[SUCCESS] Alert sent to n8n. Status: {response.status_code}")
    except requests.exceptions.RequestException as e:
        write_log(f"[ERROR] Failed to send alert to n8n: {e}")

if __name__ == "__main__":
    main()

Set Permissions

sudo chmod 750 /var/ossec/integrations/custom-n8n.py
sudo chown root:wazuh /var/ossec/integrations/custom-n8n.py

# Expected: -rwxr-x--- 1 root wazuh
ls -l /var/ossec/integrations/custom-n8n.py

Install Python Dependencies

sudo /var/ossec/framework/python/bin/pip3 install requests

Configure ossec.conf

Add this block inside the top-level <ossec_config> in /var/ossec/etc/ossec.conf, immediately before the final closing tag:

<integration>
  <name>custom-n8n.py</name>
  <hook_url>http://192.168.1.135:5678/webhook/wazuh-alerts</hook_url>
  <level>10</level>
  <alert_format>json</alert_format>
</integration>
Critical warnings:
  • There can only be one <ossec_config> root element. Do not duplicate the tag.
  • The integration block must be a top-level child of <ossec_config>, not nested inside <syscheck> or any other module.
  • If you edit via WinSCP + Notepad++, convert line endings to Unix: sudo sed -i 's/\r$//' /var/ossec/etc/ossec.conf

Restart & Verify

sudo systemctl restart wazuh-manager
sudo systemctl status wazuh-manager

Engineering Challenges Solved

These are the real-world troubleshooting scenarios that turned this lab from a checklist into an actual learning experience.

ERROR

VMware vPMC power-on failure after enabling Hyper-V

Windows 11's Virtualization-Based Security claimed exclusive CPU virtualization extensions, blocking VMware from using AMD-V for nested VMs.

FIX

Disabled Memory Integrity, ran bcdedit /set hypervisorlaunchtype off, and turned off Hyper-V, Windows Hypervisor Platform, and Virtual Machine Platform.

ERROR

Wazuh manager would not start — XML parse failure (line 0)

Copy-pasting ossec.conf over SSH mangled indentation, breaking the XML.

FIX

Switched to WinSCP for file transfer, normalized line endings with sed -i 's/\r$//', and restored the default config from upstream GitHub.

ERROR

Google OAuth redirect_uri_mismatch on private IP

Google blocks OAuth callbacks to RFC1918 addresses, returning Error 400: invalid_request.

FIX

Created an SSH tunnel (ssh -L 5678:localhost:5678) so the browser saw localhost for OAuth, while webhooks continued to bind to the IP.

ERROR

n8n "Mismatching encryption keys" crash loop

Changing N8N_ENCRYPTION_KEY between restarts made n8n unable to decrypt credentials, causing startup failure.

FIX

Wiped the Docker volume, generated a fresh key with openssl rand -base64 32, and permanently baked it into the compose file.

ERROR

Double-nested body broke field extraction

Test payloads wrapped data in an extra body key, so expressions like $json.body.rule.level returned undefined.

FIX

Reworked the curl test to send clean JSON and confirmed real Wazuh alerts would not double-wrap.

ARCHITECTURE

Moved Wazuh off the SPAN port to a routable segment

The original design placed Wazuh on the SPAN (mirror) network, which had no gateway and could not reach the n8n webhook. Recognized the mismatch and migrated the SIEM to the LAN segment to enable outbound API calls.
